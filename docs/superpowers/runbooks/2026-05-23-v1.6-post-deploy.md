## 1️⃣ Migration Neon prod (auto via Railway)

### Comment ça marche
Le push de PR #9 va déclencher un re-deploy Railway de l'API. Mais le `start` script actuel (`node dist/main`) n'exécute pas la migration. **Pour automatiser** : changer la "Custom Start Command" Railway une seule fois.

### Étapes

1. Aller sur https://railway.app → projet API `ecole-saasapi-production`.
2. **Settings** → section **Deploy** → **Custom Start Command**.
3. Coller :
   ```
   pnpm --filter=@ecole-saas/api start:prod
   ```
4. **Save** → Railway re-déploie automatiquement.
5. Le script `start:prod` (défini dans `apps/api/package.json` par cette même PR) fait :
   ```
   prisma migrate deploy && node dist/main
   ```
   → Applique `20260523000000_v1_6_tenant_brand` (ALTER TABLE ADD COLUMN brand JSONB) **avant** de démarrer l'API.

### Vérification (optionnel)

Une fois le deploy terminé (≤2 min) :
```bash
# Depuis Railway logs ou Neon console :
psql $DATABASE_URL -c "\d tenants" | grep brand
# Doit afficher : brand | jsonb |
```

Ou via l'API : créer un tenant test via `/api/admin/invite-tokens` puis appeler `/api/admin/tenant/branding` → si la column existe, retourne JSON (sinon erreur 500).

## 2️⃣ Bucket R2 `ecole-saas-tenant-assets` (manuel)

Tant que ce bucket n'est pas configuré, les uploads logo retournent **503 R2_NOT_CONFIGURED**. Le reste de l'app (couleurs, post-auth, pré-auth, settings UI sans logo) **fonctionne**.

### A. Créer le bucket

1. https://dash.cloudflare.com → **R2** → **Create bucket**.
2. **Nom** : `ecole-saas-tenant-assets`
3. **Location** : Automatic (multi-region)
4. **Storage class** : Standard
5. Cliquer **Create bucket**.

### B. Activer l'accès public

Dans le bucket → **Settings** :

**Option simple (R2.dev)** : suffit pour démarrer, URL pas brandée mais fonctionnelle.
- Section **R2.dev subdomain** → **Allow Access**
- Note l'URL `https://pub-<hash>.r2.dev` → c'est la valeur de `R2_PUBLIC_URL`.

**Option propre (V11)** : custom domain `assets.ecole-saas.com` — nécessite domaine custom (deferred V11). Reste sur R2.dev en V1.6.

### C. Configurer CORS

Dans le bucket → **Settings** → **CORS Policy** → coller :

```json
[
  {
    "AllowedOrigins": [
      "https://ecole-saas-weld.vercel.app",
      "http://localhost:3000"
    ],
    "AllowedMethods": ["PUT", "GET"],
    "AllowedHeaders": ["Content-Type"],
    "MaxAgeSeconds": 3600
  }
]
```

> Plus tard tu peux ajouter `https://*.vercel.app` si tu utilises plusieurs preview deployments. La forme `https://*.ecole-saas.com` viendra en V11 avec le wildcard DNS.

### D. Credentials API

Si tu as déjà un **Account API Token** R2 (créé pour V1.5 exports bucket) :
- Vérifie qu'il a la permission **Object Read & Write** sur les **2 buckets** (`ecole-saas-exports` ET `ecole-saas-tenant-assets`).
- Si non : régénère via **Manage R2 API tokens** → **Create API token** → Account API Token type → permissions Object Read+Write → spécifie les 2 buckets → copie Access Key ID + Secret (UNE SEULE FOIS).

### E. Env vars Railway

Aller sur https://railway.app → projet API → **Variables** :

```
R2_PUBLIC_URL=https://pub-<hash>.r2.dev
R2_TENANT_ASSETS_BUCKET=ecole-saas-tenant-assets
```

(Remplace `<hash>` par celui obtenu en §B.)

Vérifier aussi que ces 4 vars V1.5 sont présentes (sinon les uploads V1.6 + exports V1.5 retourneront 503) :
- `R2_ACCOUNT_ID`
- `R2_ACCESS_KEY_ID`
- `R2_SECRET_ACCESS_KEY`
- `R2_BUCKET_NAME` (= `ecole-saas-exports`)

Railway re-déploie automatiquement après chaque change de var.

## 3️⃣ Tests de bout-en-bout (à faire après §1 + §2)

### a. Verify migration applied
- Login sur `https://ecole-saas-weld.vercel.app/login` (en tant que SCHOOL_ADMIN existant)
- Va sur `/settings/branding`
- Le formulaire doit s'afficher avec les couleurs indigo par défaut (pas d'erreur 500)
- Change "Couleur principale" → `#ff0000` → **Enregistrer**
- Recharge → la couleur persiste

### b. Verify R2 upload
- Sur `/settings/branding`, clique **Téléverser** sur "Logo principal"
- Sélectionne un PNG ≤ 500 KB
- Si tout marche : le logo apparaît, et après save tu le vois dans la nav-bar
- Si 503 : R2 mal configuré, revoir §2.E

### c. Verify pre-auth path-based
- Logout
- Va sur `https://ecole-saas-weld.vercel.app/t/<ton-tenant-slug>/login`
- La page doit afficher tes couleurs + logo (s'il a été uploadé)
- Tester `https://ecole-saas-weld.vercel.app/t/inexistant/login` → page 404 "École introuvable"

### d. Verify email branding
- Demande un reset password depuis `/forgot-password`
- L'email reçu doit avoir :
  - Header avec la couleur d'en-tête email (ou le logo si tu l'as uploadé)
  - Lien vers `https://ecole-saas-weld.vercel.app/t/<slug>/reset-password?token=...`

## 🔧 Troubleshooting

| Symptôme | Cause probable | Fix |
|---|---|---|
| Settings page 500 "tenants.brand does not exist" | Migration pas appliquée | Vérifier Custom Start Command + Railway logs |
| Upload logo 503 R2_NOT_CONFIGURED | R2 env vars manquantes | §2.E |
| Upload logo CORS error | CORS R2 mal configuré | §2.C avec l'origin exact de ton domaine Vercel |
| Logo ne s'affiche pas après save (preview brisée) | logoUrl ne commence pas par R2_PUBLIC_URL | Vérifier R2_PUBLIC_URL Railway = URL R2.dev exacte |
| Email arrive sans couleur tenant | `tenant.brand.emailHeaderColor` non set ou template pas re-build | Régénérer brand via /settings/branding, ou check `prisma generate` post-migrate |

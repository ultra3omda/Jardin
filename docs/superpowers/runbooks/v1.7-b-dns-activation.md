# Runbook V1.7-B — Activation DNS klasso.tn + Vercel (5 min ops)

> **Déclencher ce runbook dès réception email "Domaine livré" d'OVH.**
> Estimation : 5 minutes d'ops + propagation DNS 5-30 min.

## Prérequis

- [ ] Email OVH "Domaine klasso.tn activé" reçu
- [ ] Accès dashboard OVH (anycast DNS ou zone DNS)
- [ ] Accès Vercel dashboard (projet `jardin`, team `ultra3omda-6664s-projects`)
- [ ] `CLAUDE.md` section V1.7-B relue

---

## Étape 1 — Ajouter les enregistrements DNS OVH

Dans OVH Manager > Domaines > klasso.tn > Zone DNS :

### Enregistrement A (apex)
```
Type : A
Sous-domaine : (vide = @)
Cible : 76.76.21.21
TTL : 3600
```

### Enregistrement CNAME wildcard (subdomains)
```
Type : CNAME
Sous-domaine : *
Cible : cname.vercel-dns.com.
TTL : 3600
```

> Note .tn : OVH/ATI peut mettre 24-72h pour propager les wildcard CNAME
> sur les TLD .tn. L'enregistrement A apex est généralement instantané.

---

## Étape 2 — Ajouter le domaine dans Vercel

```bash
# Via Vercel MCP ou dashboard :
vercel domains add klasso.tn --project jardin
vercel domains add "*.klasso.tn" --project jardin
```

Ou depuis Vercel Dashboard > Projet jardin > Settings > Domains :
- Ajouter `klasso.tn`
- Ajouter `*.klasso.tn`

Vercel va générer un certificat SSL wildcard automatiquement (Let's Encrypt).

---

## Étape 3 — Activer le host-resolver dans Vercel env

Dans Vercel Dashboard > Projet jardin > Settings > Environment Variables :

```
ENABLE_SUBDOMAIN_RESOLVER = true
NEXT_PUBLIC_BASE_DOMAIN = klasso.tn
```

Scope : Production + Preview (pas Local)

→ Déclencher un redeploy :

```bash
gh workflow run deploy.yml
# ou depuis Vercel dashboard > Deployments > Redeploy
```

---

## Étape 4 — Vérification DNS

Depuis ton terminal (une fois le TTL écoulé) :

```bash
# Test apex
curl -I https://klasso.tn

# Test wildcard (avec un tenant de demo)
curl -I https://demo.klasso.tn

# Attendu : HTTP 200 ou redirect 307 vers /t/demo/*
```

---

## Étape 5 — Sanity check fonctionnel

1. Ouvrir `https://demo.klasso.tn` dans le navigateur
2. Vérifier que la page `/t/demo/dashboard` charge correctement
3. Vérifier que `https://klasso.tn` charge la home marketing (ou `/login`)
4. Vérifier que `https://www.klasso.tn` redirige correctement (www = RESERVED_SLUG → pas de rewrite)

---

## Rollback si problème

```bash
# Désactiver le host-resolver sans revert du code
# Vercel Dashboard > env vars > ENABLE_SUBDOMAIN_RESOLVER → false → Redeploy
```

Le code reste dormant, zéro impact.

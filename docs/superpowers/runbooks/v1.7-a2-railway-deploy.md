# Runbook V1.7-A2 — Déploiement API NestJS sur Railway

> **Estimation : 8 minutes** (3 clics dashboard + remplissage env vars + 1er deploy).

## Pré-requis

- [ ] Compte Railway créé sur https://railway.app (gratuit, 500h/mois free tier)
- [ ] Repo GitHub `ultra3omda/Jardin` connecté à ton compte Railway (autorisation OAuth GitHub)
- [ ] La branche `feat/v1.7-a2-cloud-preview` est pushée (PR à venir)
- [ ] Une instance Postgres en cloud (Neon recommandé : free 0.5GB) avec une `DATABASE_URL` prête
- [ ] Tu connais les 2 secrets JWT actuels (depuis ton `.env` local)

---

## Étape 1 — Créer le projet Railway depuis le repo

1. Aller sur https://railway.app/new
2. Cliquer **"Deploy from GitHub repo"**
3. Sélectionner `ultra3omda/Jardin`
4. Choisir la branche : **`feat/v1.7-a2-cloud-preview`** (passera à `main` après merge)
5. Railway détecte automatiquement `apps/api/railway.json` → choix du Dockerfile : `apps/api/Dockerfile` ✅
6. Cliquer **"Deploy"**

→ Railway commence le 1er build (échouera au démarrage car pas encore d'env vars — c'est normal).

---

## Étape 2 — Configurer les variables d'environnement

Dans Railway dashboard > ton projet > Service > onglet **Variables** :

### Database (Neon)
```
DATABASE_URL=postgresql://USER:PASSWORD@HOST/DB?sslmode=require
```

### JWT (copier depuis ton .env local — JAMAIS générer de nouveaux secrets en prod sinon tous les users sont déconnectés)
```
JWT_ACCESS_SECRET=<from-local-.env>
JWT_REFRESH_SECRET=<from-local-.env>
JWT_ACCESS_EXPIRES_IN=15m
JWT_REFRESH_EXPIRES_IN=30d
BCRYPT_ROUNDS=12
```

### CORS (URLs cloud qui peuvent appeler l'API)
```
CORS_ORIGIN=https://ecole-saas.vercel.app,https://klasso-mobile.vercel.app,http://localhost:3000,http://localhost:8081
```
> Note : `http://localhost:8081` = Expo dev server pour ton smartphone via tunnel.
> Mettre à jour avec `klasso.tn` + `app.klasso.tn` une fois le domaine livré.

### Environnement
```
NODE_ENV=production
API_PORT=4000
```
> `PORT` est injecté automatiquement par Railway — `main.ts` le respecte.

### Optionnels (à activer plus tard)
```
RESEND_API_KEY=re_xxx                # pour les emails (V1.5+)
SENTRY_DSN=https://xxx@sentry.io/xxx # observability
REDIS_URL=redis://...                # cache (V11+)
```

---

## Étape 3 — Redéployer après config

Dans Railway dashboard > **Deployments** > clic sur le dernier deployment > **"Redeploy"**

→ Build prend ~3min (Docker multi-stage + Prisma generate + NestJS build)
→ Le start exécute `prisma migrate deploy && node dist/main` (migrations idempotentes)

---

## Étape 4 — Récupérer l'URL publique

Dans Railway dashboard > **Settings** > **Networking** > **"Generate Domain"**

→ Railway génère une URL : `klasso-api-production-XXXX.up.railway.app`

Test santé :
```bash
curl https://klasso-api-production-XXXX.up.railway.app/health
# Attendu : { "status": "ok", "uptime": ... }
```

Test Swagger :
```
https://klasso-api-production-XXXX.up.railway.app/api/docs
```

---

## Étape 5 — Wirer l'URL API dans Vercel (web + mobile)

Une fois l'URL Railway connue, mettre à jour les 2 projets Vercel :

**Projet `ecole-saas`** (web) > Settings > Environment Variables :
```
NEXT_PUBLIC_API_URL=https://klasso-api-production-XXXX.up.railway.app
```
Scope : Production + Preview → Redeploy

**Projet `klasso-mobile`** > Settings > Environment Variables :
```
EXPO_PUBLIC_API_URL=https://klasso-api-production-XXXX.up.railway.app
EXPO_PUBLIC_PERSONA=dev
```
Scope : Production + Preview → Redeploy

---

## Rollback si problème

Dans Railway dashboard > **Deployments** > choisir un deployment vert antérieur > **"Redeploy"**

Railway garde les 10 derniers deployments en mémoire.

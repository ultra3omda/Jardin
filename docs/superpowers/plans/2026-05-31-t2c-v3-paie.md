## 1. Objectif de la Vague 3

Générer des **bulletins de paie** sur des montants réels :
- modèles **`Payslip`** (+ **`PayslipComponent`** optionnels) liés à un `User`, tenant-scoped ;
- **calcul MVP explicite** : base = salaire du contrat ACTIVE ; brut = base + gains ; net = brut − retenues ;
- workflow **DRAFT → ISSUED** ;
- 4ᵉ onglet **Paie** sur la page `hr`.

**Pas de moteur fiscal** (CNSS/IRPP/barèmes) — explicitement reporté. PDF du bulletin = hors MVP (note de suivi).

## 2. 🛑 Checkpoint migration Prisma (validation requise AVANT `prisma migrate`)

Strictement additif (deux modèles + deux enums) :

```prisma
enum PayslipStatus {
  DRAFT
  ISSUED
}

enum PayslipComponentKind {
  EARNING
  DEDUCTION
}

// T2c V3 — Bulletin de paie d'un employé pour une période mensuelle ("YYYY-MM").
model Payslip {
  id              String        @id
  tenantId        String
  userId          String
  period          String        @db.VarChar(7) // "2026-05"
  baseSalary      Decimal       @db.Decimal(10, 3)
  grossSalary     Decimal       @db.Decimal(10, 3)
  totalDeductions Decimal       @db.Decimal(10, 3)
  netSalary       Decimal       @db.Decimal(10, 3)
  currency        String        @default("TND")
  status          PayslipStatus @default(DRAFT)
  issuedAt        DateTime?
  notes           String?       @db.Text
  createdAt       DateTime      @default(now())
  updatedAt       DateTime      @updatedAt
  deletedAt       DateTime?

  tenant     Tenant             @relation(fields: [tenantId], references: [id], onDelete: Cascade)
  employee   User               @relation("Payslips", fields: [userId], references: [id], onDelete: Cascade)
  components PayslipComponent[]

  @@unique([tenantId, userId, period], name: "payslip_per_period")
  @@index([tenantId])
  @@index([tenantId, userId])
  @@map("payslips")
}

// T2c V3 — Ligne de gain/retenue d'un bulletin (composant de calcul).
model PayslipComponent {
  id        String               @id
  tenantId  String
  payslipId String
  label     String               @db.VarChar(160)
  kind      PayslipComponentKind
  amount    Decimal              @db.Decimal(10, 3)
  createdAt DateTime             @default(now())

  tenant  Tenant  @relation(fields: [tenantId], references: [id], onDelete: Cascade)
  payslip Payslip @relation(fields: [payslipId], references: [id], onDelete: Cascade)

  @@index([tenantId])
  @@index([tenantId, payslipId])
  @@map("payslip_components")
}
```

- `Tenant` : `payslips Payslip[]` + `payslipComponents PayslipComponent[]`.
- `User` : `payslips Payslip[] @relation("Payslips")`.
- `TENANT_SCOPED_MODELS` : ajouter `'Payslip'` et `'PayslipComponent'`.
- Migration manuscrite `20260531170000_t2c_payslips/migration.sql`.
- **Format** : `Decimal(10,3)`/`TND`. Bulletins = **PII** → jamais loggés.

## 3. Règle métier — calcul MVP

Fonction **pure** `computePayslipTotals(baseSalary, components)` (testée) :
- `gross = baseSalary + Σ amount(EARNING)`
- `totalDeductions = Σ amount(DEDUCTION)`
- `net = gross − totalDeductions`
- Tous en `Prisma.Decimal` (pas de float). Recalcul à chaque ajout/suppression de composant.

Génération : `baseSalary` = `EmploymentContract` **ACTIVE** le plus récent de l'employé (sinon 400 `NO_ACTIVE_CONTRACT`). Unicité `(tenant, user, period)` → 409/400 si doublon.

## 4. Tâches (commits atomiques)

### Task 1 — Schéma + isolation (migration)
`schema.prisma` (2 modèles + 2 enums + relations), `tenant.extension.ts` (`Payslip`, `PayslipComponent`), `prisma format`/`generate`/`type-check`, migration SQL manuscrite.

### Task 2 — Module `hr` : Paie (backend)
`payroll.service.ts` (+ helper pur `computePayslipTotals`), `payroll.controller.ts`, DTOs `dto/payslip.dto.ts`. Enregistrer dans `hr.module.ts`.
Endpoints :
- `GET /hr/payslips` (admin: tous/par employé/par période ; employé: les siens)
- `GET /hr/payslips/:id` (avec composants)
- `POST /hr/payslips` (génère pour `userId`+`period` depuis le contrat ACTIVE)
- `POST /hr/payslips/:id/components` (ajoute gain/retenue → recalcul)
- `DELETE /hr/payslips/:id/components/:componentId` (recalcul)
- `POST /hr/payslips/:id/issue` (DRAFT → ISSUED + `issuedAt`)
- `DELETE /hr/payslips/:id` (soft-delete, admin)

**RBAC** : SCHOOL_ADMIN/SUPER_ADMIN = CRUD complet + émission. TEACHER/STAFF = **lecture de leurs propres bulletins** (mutations → 403). Composants modifiables uniquement tant que `DRAFT`.

### Task 3 — Specs unitaires service
`payroll.service.spec.ts` : `computePayslipTotals` (base, +gains, −retenues, net), tenant scoping, employé confiné aux siens, employé ne mute pas (403), génération sans contrat ACTIVE → 400, doublon période → erreur, `issue` met ISSUED + `issuedAt`, composant interdit si ISSUED.

### Task 4 — Client web + schémas Zod
`lib/api/hr.ts` : types + fns `listPayslips`, `getPayslip`, `generatePayslip`, `addPayslipComponent`, `deletePayslipComponent`, `issuePayslip`, `deletePayslip`. `lib/validation/hr.schemas.ts` : `generatePayslipSchema` (userId, period `YYYY-MM`), `payslipComponentSchema`.

### Task 5 — UI : onglet Paie
- `components/crud/payslip-generate-form.tsx` (employé + période), `components/crud/payslip-component-form.tsx` (label, kind, montant).
- `components/hr/payroll-section.tsx` : liste bulletins (employé/admin), badges statut, **Générer**, détail (composants + brut/retenues/net), ajout/suppression composant (DRAFT), bouton **Émettre**. États loading/empty/error+retry, toasts, invalidation.
- `app/[locale]/(app)/hr/page.tsx` : ajouter l'onglet **Paie**.

### Task 6 — Seed
Étendre `seedHr` (`seedPayroll`) : 1 bulletin idempotent par 1er employé (ISSUED, période fixe, depuis son contrat), 1–2 composants. Dates fixes.

### Task 7 — E2E + isolation
- `apps/api/test/hr-payroll.e2e-spec.ts` : admin génère depuis contrat ACTIVE (201, totaux corrects) ; ajout composant recalcule ; émission DRAFT→ISSUED ; TEACHER ne génère pas (403) mais lit les siens ; employé ne voit pas ceux d'un autre (404) ; persistance.
- Étendre `multi-tenant-isolation.e2e-spec.ts` : `Payslip` + `PayslipComponent` (scoping + cross-tenant null) + cleanup (avant suppression users).

### Task 8 — Gate + push + PR
`type-check` (api+web) + `pnpm lint` verts ; push ; PR vers `main` ; CI verte → merge auto (merge commit) ; **STOP — T2c complet (3/3)**. ADR de clôture T2c optionnel.

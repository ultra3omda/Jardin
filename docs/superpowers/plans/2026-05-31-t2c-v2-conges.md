## 1. Objectif de la Vague 2

Ajouter la gestion des **demandes de congés** avec workflow d'approbation :
- modèle **`LeaveRequest`** lié à un `User`, tenant-scoped ;
- un employé (TEACHER/STAFF) **crée** une demande et **consulte les siennes** ;
- un SCHOOL_ADMIN **approuve/rejette** (un employé ne peut **jamais** approuver ses propres congés) ;
- **solde dérivé** (jours approuvés sur l'année vs allocation annuelle constante), pas de champ stocké ;
- 3ᵉ onglet **Congés** sur la page `hr`.

Paie (V3) hors périmètre.

## 2. 🛑 Checkpoint migration Prisma (validé par l'utilisateur le 2026-05-31)

Strictement additif (un modèle + deux enums) :

```prisma
enum LeaveType {
  PAID
  SICK
  UNPAID
  OTHER
}

enum LeaveStatus {
  PENDING
  APPROVED
  REJECTED
}

// T2c V2 — Demande de congé d'un employé (User TEACHER/STAFF).
model LeaveRequest {
  id           String      @id
  tenantId     String
  userId       String
  type         LeaveType
  status       LeaveStatus @default(PENDING)
  startDate    DateTime
  endDate      DateTime
  reason       String?     @db.Text
  reviewNote   String?     @db.Text
  reviewedById String?
  reviewedAt   DateTime?
  createdAt    DateTime    @default(now())
  updatedAt    DateTime    @updatedAt
  deletedAt    DateTime?

  tenant     Tenant @relation(fields: [tenantId], references: [id], onDelete: Cascade)
  employee   User   @relation("LeaveRequests", fields: [userId], references: [id], onDelete: Cascade)
  reviewedBy User?  @relation("LeaveReviews", fields: [reviewedById], references: [id])

  @@index([tenantId])
  @@index([tenantId, userId])
  @@index([tenantId, status])
  @@map("leave_requests")
}
```

- `Tenant` : `leaveRequests LeaveRequest[]`.
- `User` : `leaveRequests LeaveRequest[] @relation("LeaveRequests")` + `leaveReviews LeaveRequest[] @relation("LeaveReviews")`.
- `TENANT_SCOPED_MODELS` : ajouter `'LeaveRequest'`.
- Migration manuscrite `20260531160000_t2c_leave_requests/migration.sql` (DB non dispo localement → appliquée en CI).

**Allocation annuelle** : constante `ANNUAL_LEAVE_ALLOWANCE_DAYS` dans `@ecole-saas/shared` (ou constante module si non partagée) — pas de magic number.

---

## 3. Règle métier — solde dérivé

- **Jours pris** = somme des jours ouvrés (`endDate - startDate + 1`, MVP = jours calendaires inclusifs) des `LeaveRequest` **APPROVED** de type `PAID` sur l'année civile courante.
- **Solde restant** = `ANNUAL_LEAVE_ALLOWANCE_DAYS - jours pris`.
- Calcul **pur** (fonction testable unitaire), exposé via `GET /hr/leaves/balance?userId=&year=`.
- Validation : `endDate >= startDate` (DTO + service).

## 4. Tâches (commits atomiques)

### Task 1 — Schéma + isolation (migration)
`schema.prisma` (modèle + enums + relations), `tenant.extension.ts` (`LeaveRequest`), `prisma format`/`generate`/`type-check`, migration SQL manuscrite.

### Task 2 — Module `hr` : Congés (backend)
Étendre le module `hr/` existant :
- `dto/leave-request.dto.ts` : Create / Review (approve|reject + note) / Query (userId?, status?) / Response / List / Balance.
- `leaves.service.ts` : `list`, `getById`, `create` (employé ou admin), `review` (approve/reject — **admin only, interdit sur ses propres congés**), `cancel`/`remove` (employé sur sa propre demande PENDING ; admin partout), `balance(userId, year)`. Helper pur `computeLeaveDays`/`computeBalance`.
- `leaves.controller.ts` : `GET /hr/leaves`, `GET /hr/leaves/balance`, `GET /hr/leaves/:id`, `POST /hr/leaves`, `POST /hr/leaves/:id/review`, `DELETE /hr/leaves/:id`.
- Enregistrer `LeavesService`/`LeavesController` dans `hr.module.ts`.

**RBAC** :
- `POST /hr/leaves` : SCHOOL_ADMIN/SUPER_ADMIN/TEACHER/STAFF (un employé pose pour lui-même ; un admin peut poser pour un employé).
- `GET` (list/balance/by-id) : admin = tous/par employé ; employé = **les siens** (filtrage forcé service).
- `POST /:id/review` : SCHOOL_ADMIN/SUPER_ADMIN **uniquement**, et `reviewedById !== leave.userId` (un admin ne s'auto-approuve pas → 403 `CANNOT_REVIEW_OWN_LEAVE`).
- `DELETE` : employé sur sa propre demande **PENDING** ; admin sans restriction.

### Task 3 — Specs unitaires service
`leaves.service.spec.ts` : `computeLeaveDays` (inclusif), `computeBalance`, tenant scoping, employé confiné aux siens, employé ne peut pas review (403), **admin ne peut pas approuver ses propres congés** (403), review met APPROVED/REJECTED + reviewedById/At, `endDate < startDate` rejeté.

### Task 4 — Constante partagée
`ANNUAL_LEAVE_ALLOWANCE_DAYS` (= 24, MVP) dans `packages/shared` (ou `hr/leaves.constants.ts` si shared non souhaité côté API). Réutilisée web (affichage solde).

### Task 5 — Client web + schémas Zod
`lib/api/hr.ts` : types + fns `listLeaves`, `getLeaveBalance`, `createLeave`, `reviewLeave`, `deleteLeave`. `lib/validation/hr.schemas.ts` : `leaveRequestSchema` (+ `endDate >= startDate` via refine), `leaveReviewSchema`.

### Task 6 — UI : onglet Congés
- `components/crud/leave-request-form.tsx` (type, dates, motif).
- `components/hr/leaves-section.tsx` : liste (employé/admin), badges statut, bouton **Demander un congé**, actions **Approuver/Rejeter** (admin, masquées sur ses propres lignes), suppression d'une demande PENDING. Carte **solde** (jours pris / restants). États loading/empty/error+retry, toasts, invalidation.
- `app/[locale]/(app)/hr/page.tsx` : ajouter l'onglet **Congés**. *(La page reste admin-only en MVP ; surface employé = note de suivi, hors V2 sauf décision — on garde l'accès direction comme V1.)*

### Task 7 — Seed
Étendre `seedHr` (ou `seedLeaves`) : 2–3 `LeaveRequest` idempotents par tenant (1 APPROVED, 1 PENDING), dates fixes, `reviewedById` = admin pour l'approuvée.

### Task 8 — E2E + isolation
- `apps/api/test/hr-leaves.e2e-spec.ts` : employé crée (201) ; employé ne review pas (403) ; admin approuve (200) ; **admin ne s'auto-approuve pas** (403) ; employé ne voit que les siens ; balance reflète l'approuvé ; persistance.
- Étendre `multi-tenant-isolation.e2e-spec.ts` : `LeaveRequest` (findMany scoping + findFirst cross-tenant → null) + cleanup (avant suppression users).

### Task 9 — Gate + push + PR
`type-check` (api+web) + `pnpm lint` verts ; push ; PR vers `main` ; CI verte → merge auto (merge commit) ; **STOP** (V3 Paie = vague suivante, validation requise).

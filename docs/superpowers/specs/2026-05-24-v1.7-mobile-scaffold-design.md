## 🎯 Objectif

Livrer 2 fondations qui débloquent V2 (modules métier) et la stratégie commerciale « 3 apps mobiles dédiées par école » :

1. **Scaffold `apps/mobile`** : un projet Expo prêt à l'emploi avec login + dashboard placeholder + brand runtime, testable via Expo Go dès le jour 1. **N'inclut PAS** la soumission stores (V12) ni les modules métier (V2+).
2. **Middleware subdomain dormant** : code Next.js host-resolver écrit dans `apps/web/middleware.ts`, mais gated par env `ENABLE_SUBDOMAIN_RESOLVER`. Activable en 5 min dès livraison `klasso.tn` (V1.7-B).

## 2. Architecture mobile (M1 + flag PERSONA)

### 2.1 Stack lockée (CLAUDE.md)

```
Expo SDK 51
├── Expo Router (file-based, mental model Next.js)
├── React Native Reusables (shadcn pour RN) — composants Button/Card/Input/Label
├── NativeWind (Tailwind RN) — tokens design partagés avec web (indigo primary)
├── Zustand (auth store)
├── TanStack Query (data fetching)
├── expo-secure-store (refresh token + tenantSlug persistés)
├── i18next + expo-localization (FR locked V1.7, EN+AR+ES V2+)
├── Jest + @testing-library/react-native (unit V2+)
└── Maestro (E2E cross-platform V12+, pas V1.7)
```

### 2.2 Flag PERSONA — design

Variable d'env de build `EXPO_PUBLIC_PERSONA` :
- Valeurs : `parent` | `teacher` | `admin` | `dev` (V1.7-A par défaut)
- En dev (`dev`) : un menu dev en haut permet de switcher de persona à chaud pour tester
- En V12 : 3 EAS Builds distincts, chacun avec `EXPO_PUBLIC_PERSONA` figé + icon/nom/bundleId customisés
- Lecture côté code : `const persona = process.env.EXPO_PUBLIC_PERSONA ?? 'dev';`

**Routing conditionnel** (Expo Router file-based) :

```
apps/mobile/app/
├── _layout.tsx                  Root layout (theme provider, query client)
├── (onboarding)/
│   ├── _layout.tsx              Stack layout pré-login
│   └── school-code.tsx          Saisie code école (slug) au 1er launch
├── (auth)/
│   ├── _layout.tsx              Stack layout (brand chargé)
│   └── login.tsx                Login form (email+password+slug pre-rempli)
├── (app)/
│   ├── _layout.tsx              Tabs ou Drawer (selon persona)
│   ├── dashboard.tsx            Dashboard placeholder « Bienvenue {firstName} »
│   └── profile.tsx              Placeholder (V2 enrichit)
└── _persona-router.tsx          Composant util qui gate écrans selon persona
```

V1.7-A livre uniquement les écrans nécessaires pour boot un user → dashboard. V2+ enrichit selon le persona (Parents voient les enfants, Teachers voient les classes, Admin voit la gestion école).

### 2.3 Brand runtime mobile

Hook `useTenantBrand()` :
- Au boot : lit `tenantSlug` depuis `expo-secure-store`, fetch `GET /api/public/tenant-brand/:slug`, persist le brand dans Zustand `useTenantStore`
- Si pas de tenantSlug → redirige vers `(onboarding)/school-code.tsx`
- Si fetch échoue (404 / network) → retry 3× puis fallback `DEFAULT_BRAND` (indigo)
- Cache stale-while-revalidate via TanStack Query (5 min comme web)

Le **theme NativeWind** consomme le brand :
- `colors.primary` = `brand.primaryColor` (hex `#RRGGBB`)
- `colors.secondary` = `brand.secondaryColor`
- Header de chaque écran affiche `brand.logoUrl` si présent, sinon `brand.tenantName`

## 3. Middleware subdomain dormant

### 3.1 Implémentation

`apps/web/middleware.ts` gagne un block conditionnel :

```typescript
const ENABLE_SUBDOMAIN_RESOLVER = process.env.ENABLE_SUBDOMAIN_RESOLVER === 'true';

if (ENABLE_SUBDOMAIN_RESOLVER) {
  const host = request.headers.get('host') ?? '';
  const slug = extractTenantSlugFromHost(host);
  if (slug) {
    // Inject as a header that Server Components can read
    request.headers.set('x-tenant-slug', slug);
    // Path-based fallback still works for users who hit /t/<slug>/...
  }
}
```

Helper `extractTenantSlugFromHost(host)` :
- `<slug>.klasso.tn` → `slug`
- `klasso.tn` (apex) → `null` (landing page générique)
- `www.klasso.tn` → `null`
- `<anything>.vercel.app` → `null` (dev/preview)
- `localhost:3000` → `null` (dev local)

Reserved slugs (ne PAS resolve comme tenant) : `www`, `app`, `api`, `admin`, `assets`, `docs`, `status`, `mail`, `support`, `dashboard`.

### 3.2 Cohabitation path-based + subdomain

Tant que `ENABLE_SUBDOMAIN_RESOLVER=false` :
- `/t/<slug>/login` reste l'URL effective (livré V1.6)
- Subdomain `<slug>.klasso.tn` n'est pas reachable (DNS pas configuré)

Quand activé (V1.7-B) :
- `<slug>.klasso.tn` ET `/t/<slug>/` fonctionnent **les deux** (transition douce)
- Email reset password peut router vers l'un OU l'autre selon `WEB_APP_URL` env Vercel

### 3.3 Tests

- Unit test `extractTenantSlugFromHost` couvre les 6 cas ci-dessus (apex, www, slug, vercel.app, localhost, reserved).
- Pas de test e2e Playwright qui touche au subdomain en V1.7-A (DNS pas live). Tests Playwright path-based V1.6 restent inchangés.

## 4. Écrans mobile V1.7-A

### 4.1 `(onboarding)/school-code.tsx`

Premier launch, l'app détecte qu'aucun `tenantSlug` n'est en `expo-secure-store` → push cet écran :

- Input « Code de votre école » (placeholder : `saint-exupery`)
- Bouton « Continuer »
- Au submit : fetch `/api/public/tenant-brand/:slug` → si 200, persist slug + brand → navigate `/login`. Si 404, message d'erreur.
- Pas de QR scan en V1.7-A (V2+).

### 4.2 `(auth)/login.tsx`

- Champs : email, password (tenantSlug auto-injecté en hidden depuis le store)
- Submit POST `/api/auth/login` (DTO V1.5 accepte déjà `tenantSlug`)
- Sur succès : persist `refreshToken` dans `expo-secure-store`, store l'access token en mémoire (Zustand), navigate `/dashboard`
- Lien « Mot de passe oublié ? » → ouvre `/forgot-password?slug=<slug>` du web dans un browser (Linking API). Le flow complet password reset reste web pour V1.7-A.

### 4.3 `(app)/dashboard.tsx`

- Header : logo de l'école + nom + bouton « Déconnexion »
- Body : « Bienvenue {firstName} ! », role badge, info tenant (slug)
- Placeholder « Modules à venir : Élèves (V2), Parents (V3), … »
- C'est l'équivalent mobile du dashboard web V1 — juste prouver que le boot complet fonctionne.

## 8. Risques + mitigations

| Risque | Probabilité | Impact | Mitigation |
|---|---|---|---|
| Expo SDK 51 incompatibilité avec Node 20+ ou pnpm workspace | Moyen | 🟠 Bloquant scaffold | Suivre exactement le guide officiel `create-expo-app --template`, tester `pnpm install` avant de commit |
| RNR (React Native Reusables) version instable | Faible | 🟢 Moyen | Pin version stable récente, fallback components simples si problème |
| API CORS bloque les requêtes mobile (différent origin) | Moyen | 🟠 Bloquant login | Vérifier `CORS_ORIGIN` Railway inclut `exp://` + `*` en dev ; en prod l'API mobile utilise le même URL que web |
| `expo-secure-store` pas dispo sur Expo Go iOS sans rebuild | Faible | 🟢 Moyen | OK avec Expo Go SDK 51, fallback `AsyncStorage` documenté si besoin |
| Build EAS V12 future demande des configs natives qu'on n'a pas en V1.7-A | Faible | 🟢 Moyen | V12 ADR documentera la migration ; V1.7-A reste pur JS Expo |
